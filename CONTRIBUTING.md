# Contributing

This repository holds the challenge, not solutions. Build your solution in your own repository ([SUBMISSION.md](docs/SUBMISSION.md)). A pull request containing solution code is closed.

---

## Questions about the rules

Open a [Question](https://github.com/voss-labs/C001-multi-tenant-isolation/issues/new?template=question.yml) issue. Search first; your question may already be answered.

If an answer changes or clarifies a requirement, the specification is updated and the change is listed in its Revisions table, with the date and a link to the issue. A requirement never gets harder after submissions open.

## Mistakes in the challenge

Typos, broken links, or two documents that contradict each other: open a pull request against `main` that fixes it and says what was wrong.

Changes to requirements, scoring or the schedule are maintainer decisions. Propose those in a Question issue, not a pull request.

## Commits

Use the same style as every other VOSS repository: `docs:`, `fix:`, `chore:`, followed by a short description of what changed.

## Conduct

Keep reviews and break reports about the code, and make them direct and specific. Attack only what the rules allow: a frozen commit running in your own sandbox, during the break round.
